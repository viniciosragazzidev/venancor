# DECISIONS

Registro de ambiguidades resolvidas. Ordem: ID, decisão, motivo.

- **D1 Valor cobrado padrão:** 1ª mensalidade + adesão (soma de faixas − desconto + adesão). Configurável por ordem via `valor_cobrado_tipo` (+ `personalizado`). Desconto abate da mensalidade, nunca da adesão, salvo `personalizado`.
- **D2 Dinheiro em centavos (integer);** conversão para reais só na borda do Asaas e na UI.
- **D3 Faixa etária:** calculada pela idade na data de criação da ordem e congelada no snapshot.
- **D4 Token do link:** 32 bytes `crypto.randomBytes`, base64url; só o SHA-256 vai ao banco (`token_hash`). Token puro existe apenas na URL enviada. Link regenerável pelo admin no "Reenviar" (invalida o anterior).
- **D5 Better Auth** (override): admin único seedado por env (`ADMIN_EMAIL`/`ADMIN_PASSWORD` no seed); cadastro público desligado. Acesso a dados só via servidor; RLS ligado sem policies.
- **D5b RLS sem Supabase Auth:** `ENABLE ROW LEVEL SECURITY` em todas as tabelas (inclusive Better Auth), **sem nenhuma policy** → anon/authenticated do PostgREST não leem nada. O app conecta por postgres.js com a connection string (role dona/`postgres`, que ignora RLS), só no servidor. `NEXT_PUBLIC_SUPABASE_*` não é usada para dados; a service-role key só serve ao Storage no servidor e nunca vai ao client. Autorização real = sessão Better Auth no admin e token na página do cliente, checados em toda action.
- **D6 Expiração:** `expira_em` vale até a assinatura. Após `assinada`, o link permanece válido para pagar mesmo passado o prazo (cliente já assinou); job/checagem lazy marca `expirada` apenas ordens `enviada/visualizada/aguardando_pagamento` vencidas há >30 dias sem pagamento. `expirada` e `cancelada` são terminais; para reabrir, criar nova ordem. Expiração é checada lazy no acesso + endpoint de cron opcional.
- **D7 Provedores fake em dev/CI:** `PAYMENT_PROVIDER=fake` e `MESSAGING_PROVIDER=fake` são o padrão sem credenciais. `FakeMessagingProvider` grava a mensagem em `mensagens` e imprime no console (OTP visível só em dev, `NODE_ENV!=production`). `FakePaymentProvider` devolve Pix/boleto de mentira e expõe rota dev `POST /api/dev/simular-pagamento` (404 em produção) que dispara o mesmo `processarWebhook`. E2E usa só fakes. `AsaasProvider`/`MetaWhatsAppProvider` ligam por env e são validados manualmente no sandbox/Meta.
- **D8 Storage em dev:** interface `StorageAdapter` (`put/getSignedUrl/delete`). `SupabaseStorage` (bucket privado `documentos`, URLs assinadas de 5 min) em produção; `LocalStorage` (pasta `.storage/`, gitignored, download via rota autenticada) quando `STORAGE_DRIVER=local`. Padrão dev: local.
- **D9 OTP:** 6 dígitos, `crypto.randomInt`, guardado com HMAC-SHA256 (segredo em env), expira em 5 min, máx 5 tentativas por código, máx 3 envios/10 min por ordem, bloqueio 15 min; usado uma vez. Rate limit em tabela (`otp_codigos`), sem Redis.
- **D10 Assinatura:** hash SHA-256 é do PDF final **antes** de anexar a página de evidências, e a página de evidências cita esse hash (evita hash circular). PDF do contrato gerado em texto via pdf-lib (sem HTML→PDF); `{{vars}}` substituídas por whitelist, valores escapados.
- **D11 Webhooks:** Asaas valida header `asaas-access-token` em tempo constante; idempotência por `unique(provider, event_id)` com INSERT ... ON CONFLICT DO NOTHING antes de processar; responde 200 em duplicado. Meta valida `X-Hub-Signature-256`. Pago só via webhook (nunca pela UI do cliente).
- **D12 Cartão:** checkout hospedado do Asaas (`checkoutUrl`/invoiceUrl) no MVP; cobrança transparente fica fora.
- **D13 Pós-assinatura:** o PDF assinado + envio por WhatsApp/e-mail corre após a assinatura; falha de mensagem não desfaz a assinatura (registrar em `mensagens` e auditoria; fallback e-mail via Resend se `RESEND_API_KEY`).
- **D14 CPF:** validado (dígitos verificadores) com Zod compartilhado em `lib/validators.ts`; logs só com máscara.
- **D15 Estrutura:** `src/` conforme SPEC §3; pt-BR nos nomes de domínio, inglês em infra. `DECISIONS.md` na raiz; contratos e plano em `docs/`.
- **D16 Dono por área:** Cofre = lib/, db/, providers/, modules/*/ lógica, webhooks, PDF, auth; Mutirão = telas (admin e `/c/[token]`), formulários, CRUDs UI, README/docs/templates, E2E. Telas consomem server actions/serviços do Cofre conforme `docs/CONTRACTS.md`; enquanto o Cofre não entrega, Mutirão usa o contrato com stub.
